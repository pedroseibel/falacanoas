# FalaCanoas: map stack and geodata research

**Date:** 2026-10-12 (first draft 2026-10-11, rewritten after fact-checking against the official pages and by running the data and the browser tests; every check is listed in the [Verification log](#verification-log)).
**Marker:** `[não verificado]` means the claim could not be confirmed from a primary source in this session. There are no other open markers.

---

## TL;DR

1. **CARTO changed its rules two weeks ago (Basemap Terms of 2026-09-29).** An API key is now mandatory on every basemap URL. Free: 5 M tile requests/month for non-commercial use (personal, educational, research, non-profit), 1 M/month for commercial use; above that Basemaps Commercial is US$500/month (10 M) or US$1 500/month (50 M). Attribution `© OpenStreetMap contributors, © CARTO` is required, and CARTO may suspend free access "at any time, in its sole discretion". The draft's style URLs were wrong (404); the real ones are `https://basemaps.cartocdn.com/gl/{voyager|positron|dark-matter}[-nolabels]-gl-style/style.json?key=KEY`.
2. **No open-source programme, but no need for one.** CARTO's free non-commercial tier already covers non-profits; "Grants for Good" (https://carto.com/grants/) gives small non-profits one year of the CARTO *platform*, not basemaps. The draft's `carto.com/social-impact` link is a 404. Caveat: "commercial" includes use "operated by or on behalf of a business", so the legal operator of FalaCanoas matters.
3. **Alternatives:** OpenFreeMap needs no key and has no request limits (commercial use allowed, no SLA). Stadia free is 200 000 credits/month, non-commercial only (the draft said 600 k). MapTiler free is 5 000 map sessions plus 100 000 API requests per month, non-commercial, logo required. Protomaps is self-hosted PMTiles (planet ≈ 120 GB, extractable by region). The OSM raster tile servers are best-effort with no SLA, need a Referer, forbid offline/bulk use and may block without notice.
4. **MapLibre GL JS is v6.14.0** (published 2026-10-11; the draft said v4.x). v6 is **ESM-only**, needs WebGL2, and weighs **≈ 439 KB gzip** (285 KB main + 143 KB worker + 10.5 KB CSS), not 140 KB.
5. **file://:** tested in headless Chromium: v6 does **not** run from a `file://` page (worker fails; local ESM blocked by CORS). v5.24.0 (UMD) does, as long as GeoJSON is inlined rather than fetched by URL.
6. **Geodata is sound, one mislabel:** IBGE Censo 2022 has the 18 Canoas bairros, all valid, no overlaps/gaps, names match the Prefeitura's except "Ilha das Graças" (IBGE) versus "Ilha das Garças" (Prefeitura). `canoas-bairros-simplified.geojson` is **not simplified** (identical to the shapefile, 14-15 decimals), and the CRS is SIRGAS 2000, not WGS84.
7. **Web outputs are tiny:** `data/web/` has `canoas-limite`, `canoas-bairros`, `canoas-cheia-2024` GeoJSON = 55.8 KB raw / 11.3 KB gzip in total, plus `canoas-bairros.svg` (10.8 KB / 4.4 KB gzip). For scale, the gov-br critique's 3.47 MB eager load is about 300 times the gzipped size of the three GeoJSON files.
8. **Flood 2024:** Copernicus EMSR720 exists (Charter activation 875) but its 5 AOIs are all in the Taquari valley; **none touches Canoas**. The shipped layer is the UFRGS database (CC BY 4.0): 63.2 km², 48.3 % of the municipality, cross-checked against the Prefeitura's own layer (IoU 0.91).
9. **The Prefeitura has a GIS portal:** GeoCanoas, https://geo.canoas.rs.gov.br (ArcGIS Enterprise, public REST services, bairro layers, flood layer, 2025 orthophoto). No reuse licence is stated, so ask before redistributing.
10. **Nominatim:** 1 request/s absolute maximum, identifying Referer/User-Agent, no autocomplete, no systematic or bulk queries. It does send `Access-Control-Allow-Origin: *`, so the draft's "CORS blocks it" was wrong. Assign the bairro by point-in-polygon on our own GeoJSON, not with a geocoder.

### Recommendation

**(a) Landing page (pt-BR, sign-ups by bairro, scoreboard and map preview).** No map library, no tiles, no key, no third party at all.
- Inline `data/web/canoas-bairros.svg` into the HTML (4.4 KB gzip). It has one `<path id="b-<IBGE code>" data-name="<nome>">` per bairro; style it with CSS (`path{fill:…}`) and make the paths clickable.
- The bairro picker is a native `<select>` of the 18 names (value = `CD_BAIRRO`) with the SVG as a progressive enhancement that sets the select on click. Works from `file://` and on 3G.
- The scoreboard preview is the same SVG coloured by CSS classes (days open by bairro). The flood layer can be added as one more `<path>` generated by `scripts/build_web_data.py` if wanted.
- Do **not** ship MapLibre, a basemap or a geocoder on this page. If a "real map" is wanted later, load it only after a click.

**(b) The eventual app.**
- MapLibre GL JS **6.x** from npm with a bundler (v6 is ESM only; pin the version; GeoJSON for bairros inline or from the same origin).
- Basemap behind a single config constant. Default **OpenFreeMap Positron** (`https://tiles.openfreemap.org/styles/positron`): no key to leak in an open-source repo, no limits, commercial use allowed, but also no SLA. **CARTO** (Positron or Voyager, optionally `-nolabels` under our own bairro layers) is a perfectly good second skin if the founder wants it, with a free non-commercial key restricted to our domain; but it adds a key, a 30-day cache cap and terms that changed on 2026-09-29. Exit plan for either: a Canoas extract as a Protomaps PMTiles file on our own static hosting.
- Assign the bairro with a point-in-polygon test on `canoas-bairros.geojson` (client and server); use reverse geocoding only to suggest a street line, one request per user action, through our own backend with caching and an identifying User-Agent.
- Avoid the OSM raster tiles, Stadia and MapTiler free tiers for a public civic app (no SLA / non-commercial / logo constraints).

### Customising

Styles are standard MapLibre style JSON (OpenMapTiles schema). Changing colours or hiding layers works at runtime with `map.setPaintProperty` / `setLayoutProperty`, or by hosting an edited copy of the JSON (CARTO's own page suggests Maputnik). No paid plan or CARTO Builder is needed. For a bairro choropleth use a `-nolabels` style and put our layers above it.

```js
const map = new maplibregl.Map({
  container: 'map',
  style: 'https://basemaps.cartocdn.com/gl/positron-nolabels-gl-style/style.json?key=' + CARTO_KEY,
  center: [-51.18, -29.92], zoom: 11,
});
// keep the attribution control visible: © OpenStreetMap contributors, © CARTO
```

## 3. Front end: MapLibre GL JS

### Version and weight (npm registry and jsDelivr, 2026-10-12)

- `latest` = **6.14.0**, published 2026-10-11 (6.0.0: 2026-07-22; last 5.x: 5.24.0). BSD-3-Clause. The draft's "v4.x" is two majors behind.
- v6 changes that matter (official CHANGELOG): **ESM-only** (`maplibre-gl.mjs`; the UMD `maplibre-gl.js` and the CSP bundle are no longer published), the worker is a real file (`maplibre-gl-worker.mjs`), **WebGL2 is required**, TypeScript target ES2022.
- Measured (gzip -9; brotli in parentheses): `maplibre-gl.mjs` 1 078 892 B raw → **285.3 KB** (235 KB); `maplibre-gl-worker.mjs` 508 314 B → **143.4 KB** (119 KB); `maplibre-gl.css` 83 263 B → **10.5 KB** (8.6 KB). Total ≈ **439 KB gzip**, about 363 KB brotli. v5.24.0 UMD: 1 056 837 B → 275.1 KB gzip (worker inline).
- A real v6 map over http additionally downloaded (measured on one load of OpenFreeMap Positron at Canoas z11): style 4.1 KB, sprite 3.7 + 48.7 KB, two glyph ranges 47.0 + 42.2 KB. Worker and tile traffic were not captured by the measurement, so the true first-view cost is higher than ≈ 0.6 MB **[tiles não medidos]**.
- Compare: static SVG 4.4 KB gzip. The draft's "~140 KB" was off by a factor of three, and its "estimated landing-page load 50-100 KB" is only true without MapLibre.
- Leaflet 1.9.4 (latest stable, 2023-05-18): 147 552 B → 42.4 KB gzip + 3.5 KB CSS. A 2.0 alpha exists. Leaflet is a sensible lighter option for a raster-only map but has no vector-style or feature-state support.

### Does it run from `file://`? (tested 2026-10-12, headless Chromium, SwiftShader WebGL)

| Test (page opened as `file://`) | Result |
|---|---|
| v5.24.0 UMD from jsDelivr, classic `<script>`, inline style and inline GeoJSON | works (`load` fired, polygon rendered) |
| v5.24.0 + OpenFreeMap Positron (remote style and tiles) | works (`idle`, 271 features rendered); remote CORS is fine |
| v5.24.0, GeoJSON source given as a `file://…geojson` URL | **fails** (`net::ERR_FAILED`); inline the data |
| v6.14.0 ESM imported from jsDelivr | **fails**: "Worker failed to load" |
| v6.14.0 ESM from a local file | **fails**: module blocked by CORS (origin `null`) |
| v6.14.0 with `setWorkerUrl(blob that imports the CDN worker)` | still fails (workaround not found) |
| v6.14.0 on `http://127.0.0.1` | works (`load` and `idle`) |

Gotchas: (1) other browsers were not tested **[não verificado]**; (2) the draft's reason ("web workers are not available from file://") is wrong for v5, which spawns a blob worker; (3) `fetch`/XHR to `file://` URLs is blocked, so any GeoJSON, style or sprite must be inlined or served over http; (4) OSM raster tiles require a Referer, which `file://` pages do not send; (5) key restrictions by site (CARTO) may not work for `file://`; (6) `maplibre-gl.css` is required; (7) never use `@latest` from a CDN (the draft's snippet would now return the ESM-only v6 and break).

**Therefore:** a static `index.html` that must open from `file://` should contain no map library (inline SVG). If a real map is ever required in such a file, pin `maplibre-gl@5.24.0` UMD, inline the data and use a keyless tile source.

### Lazy loading (only after a click, over http/https)

```js
// pinned, ESM, loaded only when the user asks for the real map
btn.addEventListener('click', async () => {
  document.head.insertAdjacentHTML('beforeend',
    '<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/maplibre-gl@6.14.0/dist/maplibre-gl.css">');
  const { Map } = await import('https://cdn.jsdelivr.net/npm/maplibre-gl@6.14.0/dist/maplibre-gl.mjs');
  new Map({ container: 'map', style: 'https://tiles.openfreemap.org/styles/positron', center: [-51.18, -29.92], zoom: 11 });
}, { once: true });
```

## 4. Geocoding

| Service | Policy (verified) |
|---|---|
| **Nominatim (OSM public server)** | "an absolute maximum of 1 request per second", per website/application in total; valid HTTP Referer or an identifying User-Agent (library defaults not accepted); attribution (ODbL); user-triggered use is fine "provided that your number of users is moderate"; must be switchable without a software update; "If at all possible, set up a proxy and also enable caching". **Forbidden:** autocomplete/search-as-you-type, systematic or grid reverse queries, scraping `details`, reselling. Periodic requests from apps count as bulk geocoding. Bulk: single thread, one machine, results cached. Response carries `access-control-allow-origin: *` (checked on a reverse query), so browsers can call it; the draft's "CORS blocks it" is wrong. https://operations.osmfoundation.org/policies/nominatim/ |
| **Photon (komoot)** | "You can use the API for your project, but please be fair - extensive usage will be throttled." No numeric limit, no availability guarantee, terms may change. CORS `*` on `/reverse`. https://photon.komoot.io/ |
| CARTO Geocoding API, "~100/day" | **[não verificado]**: no such free tier was found; removed. |

**Recommendation:** the bairro does not need a geocoder: run point-in-polygon on `canoas-bairros.geojson`. Reverse-geocode only to suggest a street address, one request per submission (never per map move), from our backend with a stable User-Agent (`FalaCanoas/x.y (+URL; contact)`), caching results, with the provider URL in config. No autocomplete against the public Nominatim. Data quality of OSM addresses in informal areas of Canoas: **[não verificado]**.

## 6. Flood extent, May 2024

### Findings

- **Copernicus EMS:** the activation is **EMSR720**, "Flood in Rio Grande Do Sul State, Brazil" (event 2024-05-02, activated 2024-05-03 09:04, closed, last update 2024-08-30; 5 AOIs, 16 products; also International Charter activation 875). The AOIs are Guaporé, Encantado, Roca Sales, Das Antas Dam and Santa Tereza, all in the Taquari valley; **none intersects Canoas** (checked against the municipal boundary). The public activations list queried (267 entries, latest event 2026-10-09) contains no other Brazil activation. Data: https://rapidmapping.emergency.copernicus.eu/backend/EMSR720/EMSR720_products.zip (not downloaded, since useless for Canoas). Whether an EMS account is needed and the EMS licence wording were not opened **[não verificado]**.
- **UFRGS-led volunteer effort (INPE hosts an earlier version of the same database in a folder named `IPH`): open and CC BY 4.0, but large.** Possantti et al. (2024), *Banco de dados das cheias na Região Hidrográfica do Lago Guaíba em Maio de 2024*, Zenodo v1.2, doi:10.5281/zenodo.13227745, GeoPackage 196 MB (md5 verified). The draft's "behind a paywall, academic contact needed" is wrong. Layer `analise_ada_inundacao_20240506` (ADA, water and mud seen by remote sensing on 2024-05-06 and 08) was clipped to Canoas and is what `data/web/canoas-cheia-2024.geojson` contains. The same DB has `rhguaiba_sentinel2_agua_obs_06052024_validada` (61.99 km² in Canoas, IoU 0.92 with GeoCanoas).

## 7. Mapping patterns for civic issues (corrected)

- **Clustering:** `supercluster` 9.1.0, 9 988 B raw / **4.1 KB gzip** (draft's ~4 KB confirmed). MapLibre's built-in `cluster: true` GeoJSON source is the simpler first choice.
- **H3 aggregation:** `h3-js` 4.5.0 UMD is 216 KB raw / **65 KB gzip** (the draft's "~30 KB unminified" was wrong); skip it, since bairro polygons already give the aggregation the scoreboard needs.
- **Choropleth by bairro:** set `promoteId: 'id'` on the GeoJSON source so `setFeatureState({source, id: '4304606001'}, {days_open: n})` works with the IBGE code (the draft keyed `setFeatureState` on `f.properties.CD_BAIRRO` without `promoteId`; without it, GeoJSON feature ids must be numeric); code not executed here **[não verificado em execução]**.
- **Privacy:** do not publish exact reporter points. Fuzzing ±100-200 m is an option, but keep the fuzzed point inside the bairro polygon (test with the same point-in-polygon), or show only the bairro/aggregate. Design opinion, not a verified standard.
- **Open311 GeoReport v2** (https://dev.open311.org/GeoReport_v2/) is a reasonable export shape: `service_request_id`, `status`, `service_name`, `agency_responsible`, `requested_datetime`, `updated_datetime`, `lat`, `long` (note: Open311 names the longitude field `long`).
- **Schema note:** `CD_BAIRRO` values such as 4304606001 exceed the 32-bit INT limit (2 147 483 647); store them as `TEXT` or `BIGINT`, and use `MultiPolygon` for the bairro geometry column.
- **Transit and OSM coverage:** the draft's Trensurb "RT-2, 6 stations" and its OSM sidewalk/bus-stop coverage statements are **[não verificado]** and were removed; check Trensurb's own list and Overpass before relying on them.
